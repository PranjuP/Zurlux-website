The product
PatchMortem
Patch failure triage & rollback orchestration

SCCM, Intune, WSUS and Ansible will all tell you a patch failed. None of them tell you why, and none of them will put the server back the way it was.

Root-cause triage

Agent logs are parsed against a structured errata corpus of 122 documented failure patterns across Windows Server, RHEL, Ubuntu and Debian, SQL Server and Oracle, Kubernetes, server firmware, and enterprise macOS. Matching is anchored on the error code and the failing component, so a result is a specific cause — not a category.

Rollback orchestration

Where a rollback is safe, PatchMortem performs it inside the window and confirms the host is serviceable again. Where it is not safe, it says so and stops. Nothing is undone without a policy that permits it.

Cluster awareness

Windows Failover Clustering, Pacemaker, SQL Server Always On availability groups, and Network Load Balancing are detected before any action is taken. Peer nodes are held so a remediation never takes out the quorum it was meant to protect.

An audit trail that survives review

Every detection, decision, approval, and rollback is written to an append-only record with the operator, the timestamp, and the evidence behind it. Exportable against your change record.

Failure-rate intelligence

Across the estate, PatchMortem ranks patches by observed failure rate per KB, package, and OS build — so a risky patch is known before it is scheduled, not after.

Security & data handling

You are giving us an agent on production servers. Here is exactly what it does.

Trust in this category is not a badge on a page. It is knowing what runs, what leaves your network, and what we cannot do even if we wanted to.

Data residency in India

All customer data is stored and processed in AWS Asia Pacific (Mumbai), ap-south-1. Nothing is replicated outside the region.

Least privilege by default

The agent collects patch state and servicing logs. Remediation is off until you enable it, per policy, per host group.

Signed agent, outbound only

Code-signed binaries with published hashes. The agent initiates outbound TLS — no inbound listener, no open port on your estate.

SSO, RBAC and approvals

SAML and OIDC sign-in, role-based access, and an approval gate on any action that changes a host.

Append-only audit log

Records cannot be edited or deleted by any user, including us. Retention is set by you and exported on demand.

Encryption end to end

TLS 1.3 in transit, AES-256 at rest, per-tenant key isolation, and no shared credentials between environments.

And what we do not do

  • We do not patch anything on our own initiative. PatchMortem reacts to your schedule; it does not set one.
  • We do not claim agentless coverage. Real root cause needs the servicing logs, and those live on the host.
  • We do not roll back where the rollback is unsafe — a driver, a firmware flash, or a schema change gets flagged for a human, not automated away.
  • We do not hold SOC 2 or ISO 27001 today. The controls above are built and running; the audits are on the roadmap, and we will not imply otherwise.
